# ScreenAim — Screen Sampling + ArUco Marker Detection (macOS)

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Swift](https://img.shields.io/badge/Swift-6.x-orange.svg?logo=swift)](https://swift.org)

[![OpenCV](https://img.shields.io/badge/OpenCV-5.0-blue.svg)](https://opencv.org)

A minimal viable prototype for the **phone-aiming screen-casting** scheme (Route B / Mac-side recognition):
**ScreenCaptureKit frame capture → OpenCV ArUco marker detection → Homography mapping to screen coordinates**.

Verified: 1728×1117 screen, 1280-wide downsampled capture, ~29 FPS, self-test mapping error < 1 px.

## Dependencies

```bash
brew install opencv   # OpenCV 5.0.0 with aruco module
swift build           # Swift 6.x, no Xcode project required
```

Structure:
- `Sources/OpenCVBridge/` — Objective-C++ bridge, wrapping `cv::aruco::ArucoDetector`, `getPerspectiveTransform`
- `Sources/ScreenAim/main.swift` — Capture, detection, mapping main flow

## Usage

```bash
# 1. Offline self-test: generate test scene -> detect 8 markers -> RANSAC homography validation (with occlusion simulation)
swift run ScreenAim --self-test

# 2. Generate 8 calibration marker PNGs (id0–3 at corners + id4–7 at midpoints)
swift run ScreenAim --make-markers ./markers

# 3. Transparent floating calibration layer (recommended): 8 floating markers (4 corners + 4 midpoints), auto-calibration + real-time aim coordinate output
swift run ScreenAim --calibrate                          # default 48 pt markers
swift run ScreenAim --calibrate --marker-size 24         # shrink when screen real-estate matters (recognition range shortens)
swift run ScreenAim --calibrate --inset 40 --pad 12      # adjustable inset / white-card padding

# 4. Phone streaming mode: receive JPEG frames over TCP (paired with ios/AimPhone App)
swift run ScreenAim --calibrate --serve 9100
swift run ScreenAim --calibrate --serve 9100 --aim-cursor   # additionally: bind aim point to mouse cursor (phone aims, cursor follows)

# 5. Sampling only (for manual screenCornerMap entry)
swift run ScreenAim
```

## Phone Side (ios/AimPhone)

The Xcode project is generated by XcodeGen, zero third-party dependencies (pure AVFoundation + Network):

```bash
cd ios && xcodegen generate          # regenerate project (after modifying project.yml)
open ios/AimPhone.xcodeproj          # open, select your Development Team, deploy to iPhone
```

- The iOS app only does: camera capture (720p, locked 1/60s exposure to suppress screen banding) + center aim crosshair + JPEG streaming
- **Daily device verification uses Release builds**: Run scheme is pinned to Release in project.yml (pure Swift detector is ~80× slower in Debug, measured 2026-08-18: detect_ms 8–15 ms → 640 ms, localAim 1.5 Hz)
- Protocol: TCP `[4-byte big-endian length][JPEG payload]`, 15 fps, 720p, ~100 ms latency
- Mac side `--calibrate --serve 9100` shows floating markers while receiving phone frames for recognition
- Verified with simulated streaming: 60/60 frames fully detected, mapping output stable

### DockKit Gimbal Support (Insta360 Flow 2 Pro, etc.)

- **Person tracking disabled**: This app aims at the screen, not people. `setSystemTrackingEnabled(false)` when docked; restored on background/exit
- **L1 state awareness**: `GimbalManager` subscribes to `DockAccessoryManager` dock/undock events, shows gimbal pill (model / battery on iOS 18+)
- **Button mapping** (iOS 17.4+ `accessoryEvents`, action closures injected by ContentView):
  - **Trigger hold = Function modifier** (`.button(id:)`, hold locks gimbal arm; pill scope icon turns yellow, function icons light up)
  - Smart wheel → **Brightness control** (requires trigger hold; absolute scale → incremental, ~5% per notch with tick haptic feedback; baseline always updates to prevent jumps)
  - Shutter → **Scan to pair / cancel scan** (requires trigger hold)
  - Flip → **Connect to Mac / Disconnect** (requires trigger hold, uses saved address from UI)
  - Pill icons: scope=trigger, sun.max=brightness, qrcode.viewfinder=scan, link=connect
- DockKit exists only in device SDK; adaptation uses `#if canImport(DockKit)` guards: simulator compiles down to no-ops; all paths silently degrade when no physical gimbal is attached
- Verification requirements: iPhone 12+ (SE 3/16e unsupported) + iOS 17+ (18 recommended) + physical gimbal; simulator cannot verify DockKit behavior

### Marker Size Measurements (local machine 1728×1117, 1280-wide downsampled capture)

| Marker side | Hit rate | Aim jitter σ |
|---|---|---|
| 64 pt | ~100% | < 0.1 pt |
| 24 pt | ~100% | ≈ 0.05 pt |
| 20 pt | ~0% → see note below | — |
| 16 pt | 0% | — |

Note: table above is pre-Phase 1 optimization. After Phase 1.1–1.3 (redundant 8 markers + sub-pixel corner refinement + One Euro filter), synthetic benchmark scenes (tools/make_bench_scenes.py, 1280×720 frames) show: 24 pt static σr 0.171 → 0.080 pt (−53%); 20 pt mid-distance defocus group hit rate 56% → 72%; 20 pt far group (8–15 px on frame) 34% → 44%. Real-device re-test with `--calibrate --serve` then `tools/plot_localaim.py` analyzing `scenes/localaim_*.csv` (includes detect_ms/quality columns).

**Edge localization & filter feel (WP1/WP3, 2026-08-17)**: when aiming close to edges with only 3 markers visible, falls back to affine approximation (convex hull guard 1.5×, replay three-point cluster conversion 10/10 = 100%, zero false positives outside guard); when detection insufficient, white dot coasts with velocity decay up to 5 frames instead of disappearing immediately; jump threshold blocks single-frame jumps (15 pt injection test: threshold open 0.19 pt vs closed 14.31 pt); static σ does not degrade (bench 0.080 pt flat). **Filter presets and per-knob tuning guide: [docs/aim-filter-tuning.md](docs/aim-filter-tuning.md)** (`--filter-preset stable|daily|fast` + `--dot-*` knobs; measured sweep average error: tripod-stable 1.15 pt / daily-handheld 0.66 pt / fast-response 0.40 pt).

The transparent floating layer attaches an 8 pt white backing card to each marker, ensuring ArUco quiet zone against any desktop background; window is click-through, always-on-top, and does not obstruct normal screen content. ESC to exit.

Phone camera resolution drops at close range; actual usable size will only be smaller than above.

First run requires **System Settings → Privacy & Security → Screen Recording** authorization for the terminal/Xcode running it.

## Mapping to Full Product

| Module | This Prototype | Production |
|---|---|---|
| Screen capture | ScreenCaptureKit | Same; or replace with NDI receiver (`NDIlib_recv_*`) |
| Marker detection | `OpenCVBridge.detectMarkers` | Same, can swap AprilTag for better far-distance robustness |
| Coordinate mapping | `OpenCVBridge.mapPointRANSAC` (redundant 8 markers + RANSAC) + One Euro filter | Same |
| Calibration UI | Full-screen floating layer with 8 auto-calibration markers | Same |
| Coordinate consumer | print; `CGWarpMouseCursorPosition` when `--calibrate --serve --aim-cursor` | UDP/WebSocket to phone |

## Notes

- ArUco markers **must have white margin (quiet zone)** when displayed; edge-touching detection fails
- OpenCV path in `Package.swift` is hard-coded to `/opt/homebrew/opt/opencv` (Apple Silicon Homebrew)
- Current `screenCornerMap` is sample values; actual calibration: Mac full-screen markers → record marker centers' screen logical coordinates → fill mapping table
