# IMU（陀螺仪）辅助白点定位方案

> 日期：2026-08-17 · 触发问题：手机转动与白点移动之间的结构性空窗——15fps 识别节奏
> （≤66ms）+ 100–150ms 链路滞后内，手的真实转动未被任何传感器测量，只能靠匀速外推去"猜"
>
> 前置：白点滞后优化 WP-L1（60Hz 匀速死推算外推显示，ADR-015）已落地；
> 滤波双端分层（ADR-014）、断帧滑行（ADR-013）均已存在。
> 优先级继承：**识别质量 > 传输速度 > 其他**——IMU 只做"增量传播/外推"，
> ArUco 视觉检出永远是唯一绝对锚点；任何 WP 不得劣化静止 σ 与跳变门行为。

---

## 0. 为什么是陀螺仪，边界在哪

瞄准的物理本质是**转动**：手腕/手臂转动手机，光轴方向跟着转，白点在屏幕上平移。
当前链路对这段转动完全无感知：

| 空窗 | 现状填补手段 | 缺陷 |
|---|---|---|
| 两次识别之间（≤66ms@15Hz） | WP-L1 匀速死推算 | 匀速假设，变加速/变向时即偏离真值 |
| 链路滞后（100–150ms） | 无 | 白点反映的是 ~100ms 前的手 |

陀螺仪恰好是这个空窗的天然填补者：100–200Hz 采样、延迟仅数毫秒、功耗可忽略。
**用实测转动替代匀速猜测**，是 WP-L1 运动源的直接升级。

**边界（必须在设计里钉死，防止演变成"IMU 替代视觉"）：**

1. **陀螺仪只测转动，不测平移。** 手臂平移手机时白点同样移动，但加速度计二次积分
   漂移以秒计爆炸，不可用。纯平移运动时 IMU 零收益，靠视觉检出兜底——融合结构必须
   保证"IMU 说没动"不等于"没动"，视觉纠偏周期内误差有界即可。
2. **陀螺仪会漂移。** 零偏噪声使姿态积分缓慢发散（消费级 MEMS 典型 ~1°/s 量级，
   CoreMotion 融合后显著更好但非零）。所以 IMU 外推**必须有时距封顶**，超顶原地保持，
   与 WP-L1 的 120ms 封顶同一哲学；视觉检出到达即重置漂移并更新权威位置。
3. **角增量 → 屏幕位移的比例系数不是常数。** 它依赖手机到屏幕的距离（同一转角，
   离屏幕越远白点扫过的屏幕距离越大）。不预设几何模型，**在线自适应标定**：
   每次视觉检出对之间，用"实测角增量 ÷ 视觉实测位移"更新比例系数（EWMA），
   连符号（轴向/镜像）都交给在线标定，避免手写轴向映射表在横竖屏/云台下的各类 bug。
4. **时间轴对齐是前置条件。** `CMDeviceMotion.timestamp` 与相机帧 PTS 同为
   mach boot 时钟（秒），理论可直接对齐——但理论不算数，WP-I1 用实测验证。

## 1. WP-I1 · CoreMotion 采样基线尖刺（只采不融，零行为变化）

### 机制

iPhone 端新增 `MotionSampler`（ios/AimPhone 新文件）：`CMMotionManager.deviceMotion`
100Hz 采样，记录 `rotationRate`（已扣零偏）、`attitude`（四元数）、时间戳。
**不改任何现有行为**：不融合、不上行新协议、不动滤波。

数据出口复用现有采集回传管道（protocol §10/§11 type 11 帧复合 payload 的 json 行
追加 motion 字段，只加不删）：`--replay`/CaptureIngestor 三件套流程原样可用。
这样尖刺产出的就是与视频帧逐帧对齐的运动真值数据。

离线分析新工具 `tools/plot_imu_baseline.py`，回答四个决策问题：

1. **时间轴**：motion 时间戳与帧 PTS 的对应关系是否成立（对齐残差分布）；
2. **轴向映射**：手握手机正常瞄准时，白点屏幕位移主要相关于哪两个转轴
   （竖屏/横屏各测，云台 docked/手持各测）；
3. **比例系数稳定性**：px/rad 在同距离下的散布、随距离的变化幅度——决定
   WP-I2 在线标定的收敛速度与置信门限；
4. **漂移率**：静止 30s 内姿态积分漂移量，决定外推时距封顶值（预期 120–250ms）。

### 验收

- 录制 ≥4 组采集会话（竖/横屏 × 手持/云台），每组含静止段 + 匀速横扫段 + 变向段；
- `plot_imu_baseline.py` 输出四问的结论数据表（写进验收小结，标注机型/系统/距离）；
- **决策门**：比例系数在同距离下散布 < ±20% 且漂移支持 ≥120ms 外推 → 进 WP-I2；
  不达标则方案降级为"仅 WP-L1 匀速外推"，记录结论关闭本方案。
- `swift build` 无回归；iOS 有改动须跑 xcodebuild（见 development.md）；
  采集会话 CSV/三件套入 `scenes/` 留档。

### 收益估算

零用户可感收益（纯测量），产出是 WP-I2 的全部设计参数。改动量：MotionSampler
约 80 行 + CaptureRecorder meta 一个字段 + 一个分析脚本。

## 2. WP-I2 · Mac 显示段 IMU 驱动外推（WP-L1 运动源升级）

### 机制

把 WP-L1 显示定时器的运动源从"滤波器低通速度（猜的）"换成"陀螺仪实测角增量"：

1. **上行（协议只加不删）**：localAim 控制帧追加可选字段
   `"gyro":{"t":帧PTS,"rate":[wx,wy],"scale":[sx,sy],"age_ms":N}`——
   iPhone 端把最近一次识别帧之后到上报时刻的 IMU 角速度快照（已投影到屏幕轴、
   已乘在线标定的比例系数，单位直接是 pt/s）捎带上行。旧 Mac 忽略未知字段；
   无 IMU 的旧 iPhone 不上报该字段，Mac 自动回退 WP-L1 匀速外推。
   **比例系数在 iPhone 端标定**（识别帧与运动样本同机同时钟，ADR-014 时间轴
   纯度原则的延伸；Mac 收到的直接是可用的 pt/s，不做二次换算）。
2. **Mac 显示段**：60Hz 定时器外推时，若 `gyro` 字段新鲜（age ≤ 250ms）则按
   `lastOut + gyroRate × Δt` 摆点，否则回退 `coastVel` 匀速外推，再否则原地保持。
   封顶/钳制/y 翻转全部复用 WP-L1 既有 `placeAimDot` 通路，**禁止第二份换算**。
3. **在线标定（iPhone 端）**：每对相邻视觉检出，用帧间 IMU 积分角增量与视觉实测
   位移更新比例系数 EWMA；检出质量 `homography/affine` 才参与标定，
   `coast` 帧不参与（它不是测量）；比例系数置信度不足（样本数 < 20）时
   `gyro` 字段不上报。
4. **静止死区**：`|gyroRate|` 低于阈值（初值 2pt/s，可 `--dot-*` 风格旋钮调）时
   视为零——陀螺零偏噪声在静止段不能让白点蠕动，静止 σ 验收是硬门槛。

### 验收

- `--filter-self-test` 加子测试：合成"已知角速度曲线 + 15Hz 视觉锚点"信号，
  IMU 外推轨迹 vs WP-L1 匀速外推轨迹，变向段误差 IMU 组 < 匀速组 50%；
  静止段漂移 < 0.1pt；gyro 字段缺失/过旧时行为与 WP-L1 完全一致（回归门）。
- 真机 A/B（同轨迹横扫 + 变向各 3 分钟，`--imu-display` 开/关，
  localaim CSV 新增 `imu_rate` 列、只加不删）：变向/加减速段轨迹相位差
  目标比 WP-L1 再降 ≥40%；静止 σ 不劣化；跳变门行为不变。
- CLI 开关 `--imu-display`（默认关，A/B 达标后 ADR 里再翻默认）；
  Mac 零 UI 布局改动。
- 必跑：`swift build && swift run ScreenAim --self-test --filter-self-test`；
  iOS 有改动跑 xcodebuild；一个 git commit，message 写明 A/B 结论。

### 收益估算

WP-L1 把运动中感知滞后降到 ~50–80ms 的代价是变向瞬间过冲；WP-I2 在变向/加减速段
把外推误差再砍一半以上，且运动源是实测而非假设。改动量：iPhone 标定+快照约
120 行，Mac 外推分支约 40 行，协议一个可选字段。

## 3. WP-I3 · iPhone 识别段 IMU 传播（评估先行，不达标不上）

### 动机

WP-I2 改善的是"Mac 看到的最后 15Hz 样本之间"的空窗；链路本身的 100–150ms 滞后
（whitedot-latency-plan §0 #1/#4）不变。若 WP-I1 数据显示 IMU 传播 120ms 内误差
远小于视觉帧间隔误差，则可以让 **iPhone 在识别帧之间直接输出 IMU 传播后的瞄准点**，
以低成本把有效上报新鲜度从 15Hz 提到 30Hz——对比 WP-L2（识别提频到 30Hz）的代价
是检测 CPU 翻倍，IMU 传播几乎是免费的。

### 机制（评估门后再实施）

- `ScreenLocalizer.solveAim` 下游加互补传播：最近一次视觉检出的单应/仿射变换 +
  此后 IMU 角增量 × 在线比例系数 → 传播瞄准点，`quality="imu"`（只加不删，
  旧端忽略，plot 工具按新等级统计）；视觉检出到达即重置为权威值；
- 传播上报限频 30Hz、时距封顶同 WP-I2；走同一 localAim 控制帧，带宽可忽略；
- **与 AimCoastFilter 的关系**：IMU 传播帧是"测量"不是"滑行"——参与跳变门残差
  统计、重置滑行帧计数；但与视觉帧区分等级，滤波权重评估时定。

### 验收 / 决策门

- 先出评估报告：WP-I1 数据离线模拟"若当时有 IMU 传播"，横扫滞后与轨迹误差
  对比现状/WP-L2 提频预期，**只有收益显著大于 WP-L2 且静止 σ 可保住才立项实施**；
- 实施后 A/B 门槛：横扫滞后较 WP-I2 基线再降 ≥30%；静止 σ 不劣化；
  `quality="imu"` 帧的轨迹与视觉帧轨迹无系统性偏移（比例系数漂移监控）。

## 4. 执行顺序与总验收

1. **WP-I1**（采样基线尖刺）— 零风险先测，四问数据是全方案的决策依据
2. **WP-I2**（Mac 显示段 IMU 外推）— WP-I1 决策门通过后做，A/B 达标才翻默认
3. **WP-I3**（iPhone 识别段传播）— 评估先行，与 WP-L2 提频做收益对比后决定去留

每个 WP 完成后必跑：`swift build && swift run ScreenAim --self-test --filter-self-test`；
iOS 改动必跑 xcodebuild；新增 ADR 按 docs/decisions.md 实际最大编号顺延
（当前最新 ADR-015，预计从 ADR-016 起）；docs/protocol.md（gyro 字段/quality 等级）、
docs/architecture.md（运动数据流）、docs/modules.md（MotionSampler）同步。

## 5. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 平移运动 IMU 不可见 | 纯平移时白点滞后无改善 | 设计边界 §0.1 钉死：IMU 只填转动，视觉纠偏周期内误差有界；不承诺平移场景收益 |
| 比例系数随距离变化 | 远近距离切换时外推幅度失真 | 在线 EWMA 自适应 + 置信门限（<20 样本不上报 gyro）；视觉检出每 66ms 纠偏封顶误差 |
| 轴向/镜像映射错误（横竖屏、云台姿态） | 白点往反方向跑 | 符号也交给在线标定，禁止手写映射表；WP-I1 先实测四组合（竖/横 × 手持/云台）验证可标定性 |
| 陀螺零偏噪声致静止蠕动 | 静止 σ 劣化（硬门槛） | 静止死区（默认 2pt/s）+ 静止 σ 验收为否决项 |
| 时间轴对齐不成立 | 融合输出系统性相位偏移 | WP-I1 第一问就是验证对齐；不成立则方案终止于 WP-I1 |
| gyro 字段与视频帧 TCP 排队 | 上报时效劣化 | 控制帧 <200B、noDelay 已开（ADR-009/§11 实测结论），带宽占比可忽略 |
| 云台增稳与陀螺数据语义混淆 | docked 时误以为数据不可用 | 云台转轴驱动的就是手机本体转动，陀螺照常有效——WP-I1 四组合含 docked 组实测确认 |
| 电量/发热 | 可忽略 | deviceMotion 100Hz 为系统融合常态负载，WP-I1 会话中顺手记录温升 |
