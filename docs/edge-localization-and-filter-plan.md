# 边角定位缺失修复 + 白点滤波增强方案

> 日期：2026-08-17 · 触发问题：手机贴近屏幕边角瞄准时定位识别缺失（白点消失/抖动）
>
> 数据依据：2026-08-17 四个真机会话 `scenes/localaim_2026-08-17T0*.csv`（约 2 万帧）离线统计。
> 优先级继承定位优化方案：**识别质量 > 传输速度 > 其他**。

---

## 0. 问题机制（数据证实）

无瞄准帧分两类：

| 类型 | 占比（四会话） | 机制 | 本方案是否覆盖 |
|---|---|---|---|
| 检出 0 个标记 | 75–90%（991/2454/4097/1340 帧） | 大概率未对准屏幕/全糊/反光（需回放帧进一步分离，不在本方案射程） | ✗ |
| 检出 1–3 个标记 | 10–25%（269/487/450/699 帧） | **贴近边角瞄准时，视野内只有「角标 + 相邻边中点」≤3 个标记，不够 RANSAC ≥4 对门槛** | ✓ 主攻 |

1–3 标记缺失帧的组合 Top 几乎全是空间相邻的 L 形簇：
`左上+上中+左中` 95 帧、`左下+下中+左中` 82 帧、`右下+右中+下中` 67 帧、
`下中+左中` 106 帧、`右下+下中` 88 帧……几何上完全吻合「近距离瞄角，画面只覆盖约 1/4 屏幕」。

连续无瞄准段：中位 **2 帧**（瞬时掉检为主），p90 = 11 帧，长尾是离开屏幕。

**结论：边角缺失主因不是检测能力，而是「视野内可用参考点 < 4」的几何饥饿。**
三条互补修复线：WP1 软件兜底（3 点可解 + 断帧滑行）、WP2 物理增补（角标卫星标记）、
WP3 输出滤波增强（白点轨迹质量）。

---

## 1. WP1 · 3 点仿射兜底 + 单应滑行（纯软件，零屏幕遮挡，先做）

### 1.1 仿射兜底

- 现状：`ScreenLocalizer.localize`（ScreenAimCore）匹配 <4 对即返回 `aim = nil`。
- 改动：恰好匹配 **3 对**时，退化为仿射变换（三点精确解，屏幕是平面，簇内误差仅 pt 级）。
  - `Homography.swift` 新增 `AffineTransform` 求解（3 点 → 6 参数，闭式解，无需 Accelerate）；
    或在 `Homography` 加 `init?(affineSrc:dst:)`，map 接口保持一致。
  - **发散护栏（必须）**：映射出的瞄点超出三点凸包外接范围的 1.5 倍时仍返回 nil
    （仿射不能外推透视，远离三角形后误差发散）。护栏内才接受仿射输出。
  - localAim 上报/CSV 加标志位区分输出等级：`homography`（≥4 对）/ `affine`（3 对护栏内）/
    `coast`（滑行，见 1.2）——协议只加不删，新增可选字段 `quality`，旧端忽略。
- 预期收益：观测到的三点簇帧（每会话数十至近百帧）全部转化为有效输出。

### 1.2 单应滑行（coast）

- 检出 <4 且仿射护栏也不满足时：**沿用上一有效变换外推最多 N 帧**（默认 5 帧 ≈ 330ms@15Hz），
  输出标 `quality=coast`；超过 N 帧才返回 nil。
- 现状 `registerNoAim` 连续 10 帧才重置滤波器，但期间完全无输出——滑行填的是这个空窗；
  中位缺失段只有 2 帧，收益面大。
- 与 WP3 滤波层的速度衰减外推共用同一机制（见 §3.2），不要两处各写一份。

**验收**：
- `swift run ScreenAim --self-test` 新增场景：只放 3 个相邻标记（角 + 两边中点），
  瞄点在簇内 → 有输出且误差 < 5pt；瞄点强外推（超出护栏）→ 无输出。
- 基准回放：用既有 `scenes/bench*` 与 localaim CSV 重放对比，三点簇帧转化率 ≈ 100%，
  护栏外无假阳性输出。

## 2. WP2 · 角标卫星标记（白卡周围增补定位信息，真机 A/B 后定去留）

### 2.1 布局

- 每个角标记（id0–3）**内侧沿两条边各加 1 个卫星标记**，共 8 个，id 8–15
  （DICT_4X4_50 共 50 个 id，空间充足）。
- 卫星尺寸 16–20pt（独立 `--satellite-size`，默认 18pt），自带白卡（沿用 `pad` 静区规则）；
  中心距对应角标中心沿边偏移 ≈ 主白卡半宽 + 卫星白卡半宽 + 8pt 间隙。
- 上两角沿顶边的卫星沿用 id4 的刘海约束（`safeAreaInsets.top`），不进入刘海区。
- 定位原理：近距离瞄角时角标与两颗卫星同屏，L 形三点簇变 4–5 点簇，RANSAC 可解；
  卫星只需在近距离工作（帧上 30px+，远超检测器 `minSide=8px` 下限），
  远距离掉检不影响主 8 标记。基准参照：`bench20mid` 组（20pt、屏幕占画面 56–70% 宽）
  Phase 1 后命中率 72%，卫星工作条件远好于此。

### 2.2 改动点

| 文件 | 改动 |
|---|---|
| `Sources/ScreenAim/main.swift` `Calibrator.rebuildMarkers` | `newCenters` 8 → 16 项；生成循环加 id 8–15；`centers.count == 8` 的 guard 放宽 |
| `Sources/ScreenAim/main.swift` CLI | 新增 `--satellites`（默认关）与 `--satellite-size`；calib payload 自动带新条目（markers 开放字典，协议不变） |
| `Sources/OpenCVBridge` 自检场景生成 | `makeTestScene` 支持 16 标记变体 |
| `tools/make_test_scenes.py` / `make_bench_scenes.py` | 同步支持卫星标记，新增「近距瞄角」基准组（画面只覆盖 1/4 屏幕） |
| iPhone 端 | 零改动（`ScreenLocalizer` 按 id 匹配 screenCornerMap） |

### 2.3 代价与缓解

- 屏幕白卡 8 → 16，视觉遮挡上升（既有风险登记"8 标记占屏幕空间"的延续）：
  卫星默认关、16–20pt 小尺寸、复用 `markerAlpha` 半透明滑杆。

**验收（真机 A/B，必须做）**：
- 同一贴角瞄准轨迹，关/开卫星各录 3 分钟 localaim CSV：
  边角区域（屏幕 3×3 分格的四个角格）有瞄准帧率显著提升（目标 +30pp 以上），
  中心区域静止 σ 不劣化。达标才保留默认开启，否则保持默认关并记录结论。
- 分析工具现成：`tools/plot_localaim.py` + 「ScreenAim 调试」看板 localAim 聚合 Widget。

## 3. WP3 · 白点位置滤波算法研究与增强

### 3.1 候选算法对比（瞄准点/指针轨迹场景，输入 ≈15Hz，目标：静止消抖 + 快速跟手）

| 算法 | 机制 | 本场景适配性 | 结论 |
|---|---|---|---|
| **One Euro（现状，Casiez et al. CHI 2012）** | 速度自适应截止频率的一阶低通 | 为人手指针任务专门设计，原文基准优于固定低通与简单 Kalman；静止 σ 实测已压到 0.05–0.08pt | ◎ **保留为核心**，没有比它更适合本场景的算法族 |
| Kalman / α-β（匀速模型） | 带运动模型的预测-校正 | 优点：断帧可外推；缺点：对人手急停/加速机动滞后或超调，静止消抖不如 1€ | ○ 不替代 1€；其「预测」思想吸收进滑行（§3.2） |
| Holt 双指数平滑 | 趋势跟踪 | 急停/反向时超调，白点会"冲过头" | ✗ 排除 |
| Savitzky-Golay / 滑动中值 | 窗口拟合/中值 | 零相位需未来样本 = 固定延迟；实时瞄准不可接受。3 点中值可作离群前置，但 RANSAC 已剔大头 | ✗ 不作主滤波 |
| 粒子滤波 / IMM 多模型 | 多假设机动跟踪 | 调参复杂度远超收益 | ✗ 过度工程 |

**结论：主滤波器不更换**。One Euro 就是这个场景的最优解（它本来就是为「手抖指针」发明的）。
真正该补的是三个增强（现状的两个缺口 + 一个结构问题）。

### 3.2 三个增强（统一实现于 ScreenAimCore）

1. **跳变门限（outlier gate）**：新样本与滤波预测值距离 > k × 近期输出 σ 时，
   本帧输出保持预测（或大幅降权），不计入状态更新。防 RANSAC 漏网的 5–20pt 级
   单帧跳变把白点甩出去。k 默认 2.5，可关。
2. **断帧滑行（coast with decay）**：无瞄准帧按最近低通速度外推，速度指数衰减
   （半衰期 ≈100ms），最多 N 帧（默认 5），与 WP1 §1.2 同一机制——
   实现在 `OneEuroFilter` 旁的新文件 `AimCoastFilter.swift` 或扩展 OneEuroFilter，
   双端（iPhone `ScreenLocalizer`、Mac `Calibrator.dotFilter`）共用。
3. **双端滤波分层解耦（结构修正）**：现状 iPhone 一段 1€ + Mac `dotFilter` 二段 1€
   串联，参数互相耦合（两段都消抖，横扫滞后叠加）。
   - iPhone 段：强消抖（对原始识别噪声），参数按 15Hz 识别节奏标定；
   - Mac 段：只负责 15Hz 上报 → 60fps 显示刷新之间的插值平滑 + 跳变门 + 滑行，
     不再做重复消抖。
   - 两段参数显式分离命名，注释写清各管什么。

### 3.3 口语化调参面板（本 WP 的硬性交付物）

实现完成后必须交付一份「人话调参指南」（写进 `docs/` 并挂到 README 实测表附近），
底层参数一律映射为口语化选项：

**预设三档**（底层映射值为实现时的起点，实测后可调）：

| 预设 | 适用场景 | minCutoff | beta | 滑行帧数 | 跳变门限 k |
|---|---|---|---|---|---|
| 「稳如三脚架」 | 演示、精细点击 | 0.6 | 0.25 | 3 | 1.8（严格） |
| 「日常跟手」（默认） | 通用 | 1.0 | 0.5 | 5 | 2.5 |
| 「疾速响应」 | 快速拖拽、大范围甩动 | 1.6 | 1.0 | 8 | 4.0（宽松） |

**单项微调旋钮**（口语化描述 → 底层参数 → 往哪边调是什么感觉）：

- 「静止时白点有多稳」→ minCutoff（0.4–2.0）：往低调更稳但慢移开始拖，往高调慢速抖动会透出来
- 「甩动时有多跟手」→ beta（0.2–1.5）：往高调快速移动更贴手但高速段会带点抖，往低调横扫会变"肉"
- 「识别中断后白点继续滑多久」→ 滑行帧数（0–10）：调 0 = 一丢就隐（现状），调高 = 掉检时白点惯性滑行更久
- 「跳变过滤多严格」→ k（1.5–4.0 / 关闭）：往低调几乎不甩但也可能把真实快速移动当跳变压住，调关闭 = 现状行为

**验收**：
- 静止 σ 不劣化于现状（0.05–0.08pt 级）；注入人工跳变（单帧偏移 15pt）白点不甩；
  断流 3 帧内白点平滑滑行不消失；「疾速响应」档横扫滞后明显小于「稳如三脚架」档
  （数值写进验收小结）。
- 口语化调参表随代码同提交，每个旋钮有「往哪边调会怎样」的一句话说明。

## 4. 执行顺序与总验收

1. **WP1（仿射兜底 + 滑行）** — 纯软件，零风险先行
2. **WP3（滤波增强 + 口语化调参面板）** — 纯软件，与 WP1 共用滑行机制
3. **WP2（卫星标记）** — 默认关闭落地，真机 A/B 达标后再考虑默认开启

总验收（每个 WP 完成后必跑）：
- `swift build && swift run ScreenAim --self-test`（自检场景按各 WP 要求扩充）
- iOS 侧改动后：`cd ios && xcodegen generate && xcodebuild -project AimPhone.xcodeproj -scheme AimPhone -destination 'generic/platform=iOS' build`（签名失败可接受，编译错误不可接受）
- 真机冒烟：配对 → calib 下发 → 四角/四边贴近瞄准轨迹 → localaim CSV 对比

## 6. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 仿射护栏太松，强外推输出误导性坐标 | 白点飞到错误位置 | 护栏 1.5× 凸包 + `quality` 标志下游可区分；自检覆盖外推拒绝场景 |
| 跳变门限误压真实快速移动 | 横扫变钝 | k 可关、预设分档；真机横扫回归 |
| 卫星白卡视觉遮挡投诉 | 用户观感 | 默认关、小尺寸、半透明滑杆；A/B 不达标不开启 |
| markers=0 类缺失（占大头）不在本方案射程 | 期望管理 | 方案 §0 已声明边界；后续单独立项回放帧分离「未对准 vs 对准全丢」 |
