# ScreenAim 注释系统规范

本项目注释的目标读者是**三个月后的自己和接手的协作者**。注释解释"为什么"，
代码本身表达"做什么"。所有注释用中文。

## 五级注释体系

| 级别 | 形式 | 位置 | 内容 |
|---|---|---|---|
| L0 文件头 | `//` 块 | 每个源文件顶部 | 文件职责一句话 + 所属模块 + 关键约束 |
| L1 类型文档 | `///` | 每个类型/协议 | 职责、使用约束、线程/Actor 上下文 |
| L2 成员文档 | `///` | 公开/内部 API | 语义、参数单位与取值范围、副作用 |
| L3 行内说明 | `//` | 非显然的单行/小块 | 为什么这么做（不翻译代码） |
| L4 区块划分 | `// MARK: -` | 文件内分区 | 与文档目录一致的功能分区 |

## 模板

### L0 文件头（每个新文件必须有）

```swift
//
//  <文件名>
//  <所属模块> — <一句话职责>
//
//  关键约束：<线程模型 / 坐标系 / 平台限制等，没有则省略此行>
//
```

### L1/L2 doc comment

```swift
/// 一句话语义（可被 Quick Help 直接引用）。
///
/// 约束与副作用：线程上下文、单位、取值范围、失败行为。
/// - Parameters: 仅在语义不明显时逐个写
/// - Returns / - Throws: 同上
```

### L3 行内说明的规则

- 写**原因、单位、实测数据、外部约束**（系统 bug、硬件行为、协议要求）
- 不写代码本身的复述：`i += 1  // i 加一` ❌
- 涉及实测数据时给条件：`// 24pt 标记实测命中率 ~100%（1280 宽降采样）`

## 标记词（grep 友好，全项目统一）

| 标记 | 含义 | 示例 |
|---|---|---|
| `// NOTE:` | 设计动机/背景知识 | `// NOTE: 弹窗期连接会永久卡死，必须看门狗重启` |
| `// WARNING:` | 改这里容易踩坑 | `// WARNING: NSView 坐标左下原点，需翻转 y` |
| `// HACK:` | 绕过外部缺陷的临时方案，注明起因 | `// HACK: CIQRCodeGenerator 1px=1模块，依赖该实现细节` |
| `// TODO:` | 明确要做的事，注明方向 | `// TODO: 产品化时换 UDP 回传（见 README 对照表）` |
| `// DEBUG:` | 调试用途、稳定后可删 | `// DEBUG: 云台事件历史上屏，定位扳机通道用` |

禁用裸 `FIXME`；问题要么修，要么转成 `TODO`/`WARNING` 并写清条件。

## 维护约定

1. **注释与代码同提交**：改行为必须同步改注释；过期的注释比没有更糟。
2. **决策级注释进 docs/decisions.md**：凡是"为什么选 A 不选 B"且影响跨文件的，
   在代码处留一行 `// NOTE: 见 ADR-00X`，详情写 ADR。
3. **删除代码时删除其注释**，包括 MARK 分区。
4. Review 检查项：新文件有 L0？公开 API 有 L2？非显然逻辑有 L3？标记词用对？
